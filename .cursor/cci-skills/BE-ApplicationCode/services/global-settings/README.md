# Global Settings Service

## Overview

Global Settings Service manages rule configurations used to derive shipment-level global behavior (for example shipment type mapping), keeps DRL rules synchronized in Redis, and exposes APIs for CRUD, status changes, search, audit history, and manual sync.

The service runs as a Spring Boot application and depends on the shared `persistence-layer` module for entities, caching abstraction, JPA configuration, common API response handling, and exception model.

## Tech Stack

- Java 21 (Gradle toolchain)
- Gradle 9.4.1 wrapper
- Spring Boot `3.5.13`
- Spring Data JPA (PostgreSQL)
- Spring Data Redis
- Drools (`kie-api`, `drools-core`, `drools-compiler`, `drools-mvel`, `drools-templates`)
- Javers audit history
- AWS SES SDK integration
- JaCoCo + SonarQube plugins
- Lombok
- Internal shared dependency: `com.customcharge:persistence-layer:1.0.1`

## Features

- Full CRUD for global rules via inherited abstract controller endpoints.
- Audit history query by group and date range (`/v1/rules/history`).
- Rule status toggle (`/v1/rules/{id}/status`).
- Criteria-based paginated search over global settings (`/v1/rules/criteria`).
- Manual rule/cache sync API (`/v1/rules/sync`).
- DRL generation from rule templates (`templates/global-rule-template.drt`).
- Redis-backed DRL map caching with key pattern `rule:{destination}:{shipmentType}`.
- Distributed sync lock using Redis key `lock:globalSetting:sync`.
- Automatic activation/deactivation of rules by date window during sync.
- Javers-backed change tracking for `GLOBAL_SETTING` entity group.

## Architecture Overview

Design style: **Layered architecture** (`Controller -> Service -> DAO/Repository`) with **cache-first operational sync** and **rules engine integration**.

Request/processing flow:

1. API request hits `GlobalSettingController`.
2. Business logic is handled by `GlobalSettingServiceImp` or `GlobalSettingSyncService`.
3. JPA persistence happens through `GlobalSettingDao` and `GlobalSettingRepository`.
4. DRL content is generated by `TemplateDrlRuleConverter`.
5. DRL cache keys/maps are maintained by `GlobalSettingDrlCacheManager`.
6. Audit queries are served by `GlobalSettingAuditService` via Javers.
7. Standardized API wrapping and global exception handling are provided by the shared persistence module auto-config.

There is no background scheduler in this service; sync is triggered explicitly through API.

## Setup & Run Instructions

### Prerequisites

- JDK 21 (toolchain compilation)
- PostgreSQL instance with expected schema/tables
- Redis instance for lock/cache/rule map usage
- Optional: AWS credentials for SES

### Run Commands (Gradle)

```bash
./gradlew clean build -x test
./gradlew test
./gradlew bootRun
```
### Running Port :8080
### Notes

- No test sources are currently present (`src/test/java` empty), so `test` phase runs with no test classes.
- Build includes JaCoCo configuration; report generation is skipped when no tests exist.

## Logging & Monitoring

- Uses SLF4J logging across services (`log.info`, `log.error`, `log.debug`).
- Key operational logs:
  - create/update/delete/status transitions
  - sync lifecycle and lock acquisition/release
  - DRL cache rebuild counts
  - audit query execution boundaries
- Health and standardized response/error handling are provided by imported persistence-layer components.
